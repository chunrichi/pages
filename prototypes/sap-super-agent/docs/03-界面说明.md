## 01 · 注册 / 账号绑定

**路由**：`#/welcome` · **截图**：[auth-welcome](../screenshots/auth-welcome.png)

- **目标**：让新用户理解「账号关联小组 + 一次性链接 + 设备绑定」并完成注册。
- **布局**：左侧品牌叙事（52%）+ 右侧表单（48%）；左侧展示 3 步流程，右侧 400px 表单。
- **关键元素**：姓名、企业邮箱、小组 select、工作视角卡片（SAP 业务 / SAP IT）、指纹说明、主按钮、已有设备 / 重新注册入口。
- **状态**：必填校验、邮箱格式、小组成员上限（后端）、发送中。
- **交互**：提交 → Toast + 跳转 `#/verify`；工作视角选择；「重新注册」→ `#/rebind`。
- **数据**：邀请记录、小组、角色；不展示内部 token。

## 02 · 邮件已发送

**路由**：`#/verify` · **截图**：[auth-bind](../screenshots/auth-bind.png)

- **目标**：告诉用户去邮箱点击链接，并展示可预期的时间窗。
- **关键元素**：邮件预览卡（发件人、主题、正文、按钮）、10 分钟倒计时环、重发入口、演示直达链接。
- **状态**：倒计时进行中 / 已过期；重发冷却。
- **交互**：点击邮件内按钮 = 演示打开链接；更换邮箱返回注册。

## 03 · 设备绑定

**路由**：`#/bind` · **截图**：[auth-bind](../screenshots/auth-bind.png)

- **目标**：把「正在校验什么」变成可见过程，建立信任。
- **布局**：单列 460px。校验步骤 + 成功面板 + 设备信息 + 安全说明。
- **关键元素**：5 个校验项（链接、指纹、IP、用户名、签发凭证）、设备卡、安全提示。
- **状态**：校验中（逐步完成）/ 成功 / 失败（错误原因）。
- **交互**：完成后展示「进入工作台」；取消 / 重新注册入口。
- **动效**：步骤逐个从 active → done；成功面板淡入；减少动效时直接展示结果。

## 04 · 重新注册设备

**路由**：`#/rebind`

- **目标**：换设备时安全地解除旧设备。
- **关键元素**：邮箱、账号信息、已绑定设备列表（旧设备 / 当前设备）、警告 callout、发送新链接。
- **状态**：旧设备「待解除」、当前设备「当前」；提交后进入 `#/verify`。
- **安全**：红色错误说明 + 旧设备吊销提示。

## 05 · 工作台总览

**路由**：`#/home`（`?view=it` 为 IT 视角） · **截图**：[业务](../screenshots/home.png) · [IT](../screenshots/home-it.png)

- **状态**：业务 / IT 两种视角：业务看需求进度、待我确认与上线窗口；IT 看任务与租约、等待回答、队列健康与 Agent 运行；空状态；数据加载 skeleton。
- **交互**：需求行点击进详情；门禁卡进评审；「新建需求」；工作视角切换。
- **动效**：首屏交错入场；数字计数；进度条填充；live 脉冲。

## 07 · 新建需求（三步）

**路由**：`#/demands/new` · **截图**：[step1](../screenshots/new-demand-1.png) · [step2](../screenshots/new-demand-2.png) · [step3](../screenshots/new-demand-3.png)

- **目标**：把「提需求」拆成可理解的三个阶段，并且让 AI 澄清成为可确认的结果而不是黑盒。
- **步骤**：
  1. **需求信息**：标题、描述、验收标准、优先级、期望上线、JIRA、类型、负责人多选、附件、知识库范围。
  2. **AI 澄清**：检索链、AI 复述、3 个澄清问题（已答 / 未答）、用户补充、右侧澄清结论与引用。
  3. **确认提交**：需求摘要、Teams 通知预览、小组 / 模板 / 门禁 / 通知时机、提交。
- **状态**：草稿保存、必填校验、AI 生成中、重新生成、提交中、提交成功。
- **交互**：步骤切换；负责人 chip 增删；附件上传；知识库 chip；澄清选项；提交确认弹窗 → 成功清单。
- **动效**：AI 澄清逐步出现；sticky 底部操作；进度条。
- **数据**：草稿、知识库引用、负责人、提交事件。

- **状态**：阶段推进中、等待门禁、AI 生成中、失败 / 阻塞、已完成。
- **交互**：Tab 切换、在 VSCode 打开、复制深链、导出、更多操作、关注。

## 09 · 文档评审

**路由**：`#/demands/R-2041/doc/functional-design` · **截图**：[doc-review](../screenshots/doc-review.png)

- **目标**：像审阅文档一样审阅 AI 产出，并且把批注、版本与门禁放在一起。
- **布局**：三栏 —— 左目录 / 版本（172px）、中文档（1fr）、右批注（322px）。
- **关键元素**：文档标题、版本、Markdown 标记、状态、作者、评审时限；预览 / 源码切换；行内批注 pin；批注卡（引用、评论、解决）；AI 建议；目录与统计；门禁条。
- **Markdown**：文档固定为 Markdown；「源码」模式展示只读 `.md` 内容；「下载 .md」导出当前版本；所有修改 / AI 重生成都产生新版本。
- **状态**：批注未解决 / 已解决；版本对比开启；门禁 2/3；通过 / 驳回弹窗；AI 生成中 / 已生成 v3。
- **交互**：点击 pin 联动批注；添加批注；@AI；解决；显示 diff（ins/del）；「交给 AI 生成新版本」展示未解决批注清单并生成 v3；通过 / 驳回；版本切换（原型为展示）。
- **动效**：目录 scroll spy；批注高亮；门禁决策弹窗。

## 14 · CRQ 模板

**路由**：`#/tools/crq/templates` · **截图**：[crq-templates](../screenshots/crq-templates.png)、[crq-templates-base](../screenshots/crq-templates-base.png)、[crq-template-options](../screenshots/crq-template-options.png)

- **目标**：小组维护自己的 CRQ 模板（字段、下拉选项、版本）；平台管理员只维护平台基础模板。
- **权限**：小组模板只显示本组，其他小组不可见；平台管理员比小组管理员多一个「平台基础模板」范围，仍不提供跨组视图；普通成员只读（隐藏新建 / 编辑 / 发布，显示只读条）。
- **布局**：三栏（模板列表 220px、版本列表 320px、模板详情 1fr）；顶部 segmented 切换「本组模板 / 平台基础模板」（后者仅平台管理员可见）。
- **关键元素**：模板列表（版本数 / 当前版本 / 使用量）、版本行（v3 当前发布 / v2 已归档 / 草稿）、字段表（名称、类型、来源、默认值与选项数）、下拉选项概览（默认值高亮）、预览表单、发布新版本。
- **状态**：当前发布 / 已归档 / 草稿；只读。
- **交互**：切换模板 / 版本；新建（基于平台基础模板或空白）、复制；编辑模板（名称、说明、下拉选项维护）；「从 ChaRM 拉取」值列表后勾选添加到选项，点击选项设为默认值；保存草稿 / 发布新版本（旧版本自动归档）；预览表单。
- **动效**：新选项与版本行淡入；ChaRM 拉取有 loading；抽屉 360ms 滑入；`?shot=1` 下直接终态。

  - 左栏「我的账号」：头像、姓名、邮箱；只读信息行为所属小组、业务角色、管理权限、邀请人、加入时间。
  - 左栏「一次性链接」：平台策略（有效期 10 分钟、仅 1 次、绑定要素、设备凭证 180 天、旧设备处理）；卡片底部管理员显示「去管理控制台」链接。
  - 右栏「当前设备」：设备信息、重新注册此设备 / 解除绑定；下方「已解除设备」与旧设备吊销提示。
  - 右栏「安全事件」：绑定、重新注册、指纹不匹配、吊销记录；管理员可跳转审计日志。
- **通知规则**：事件订阅矩阵（Teams / 邮件 / 站内）+ 免打扰时段；按账号生效，与视角无关。
- **状态**：已绑定 / 未绑定；通知保存中；管理员页头显示「管理控制台」按钮，普通成员显示「成员」pill（一次性链接卡底部入口也只在管理员时出现）。
- **交互**：切换 tab；开关即时保存；重新注册；解除绑定（二次确认）；管理员前往管理控制台。

## 20 · 管理控制台

**路由**：`#/admin`（`?tab=groups` 默认 / `?tab=integrations&sub=connection|params` / `?tab=audit`；`?as=member` 为无权限页，`?as=groupadmin` 为小组管理员视角） · **截图**：[小组与成员](../screenshots/admin-groups.png) · [连接与凭据](../screenshots/admin-integrations.png) · [维护抽屉](../screenshots/admin-maintain.png) · [小组参数](../screenshots/admin-integration-params.png) · [参数抽屉](../screenshots/admin-integration-params-edit.png) · [代为维护](../screenshots/admin-integration-params-delegate.png) · [审计日志](../screenshots/admin-audit.png) · [无权限页](../screenshots/admin-denied.png)

- **目标**：把小组与成员、集成维护、审计收进一个只有管理员能进的控制台；每个异常都有修复入口，每次管理动作都留痕。
- **布局**：页头（「管理控制台」+ 管理级别 pill（平台管理员 / 小组管理员））+ 待处理条（仅小组与成员 tab）+ 顶部横向 tabs（小组与成员 / 集成与维护 / 审计日志）+ 内容区；「集成与维护」tab 内再分二级 segmented（连接与凭据 / 小组参数）。
- **待处理条**：有异常时才出现，只在「小组与成员」tab：集成需维护（去维护 → 集成与维护 tab 并打开维护抽屉）、邀请待接受（去查看 → 小组与成员 tab）；每项一键落到对应位置。
- **小组与成员**：
  - 小组卡（三张，管理员视图的选择器；我的小组高亮）：小组名、Key、成员数、管理员、默认模板；「管理小组」打开配置弹窗（Key 只读，无权限时禁用）；「新建小组」仅平台管理员出现。
  - 成员表：成员、邮箱、业务角色、管理权限、设备绑定、最近活跃、行操作；待接受邀请行内给「重发 / 撤销」。
  - 行操作弹窗：调整业务角色、设为 / 取消小组管理员、重发邀请或绑定链接、解除设备绑定、转移到其他小组（仅平台管理员）、移除成员；不能改自己的业务角色 / 管理权限，最后一名小组管理员不可降级 / 移除（禁用 + 原因）。
  - 右侧：成员维护权限（两级管理员职责、最后一名管理员保护、跨组转移、审计留痕）、成员变更（最近变更，可进审计日志）。
- **集成与维护**：tab 内用二级 segmented 分两个子视图；连接与凭据是平台级，小组参数按小组维护（权限与继承见 [06 §4.5](06-角色权限与管理.md#45-两级配置通用连接--小组参数)）。
  - **连接与凭据**：
    - 集成卡：6 张（Teams / SMTP / JIRA / SolMan / ChaRM / AI 网关）+ Helix 宽卡；每张有状态（已连接 / 同步中 / 需处理 / 已停用 / 未配置）、按集成展示的元信息、按状态变化的主动作 + 「维护」；需处理卡带错误摘要。
    - Helix 宽卡多一个「小组参数」入口，直达本组的小组参数视图。
    - 维护抽屉：连接信息、凭据（掩码 / 轮换 / 到期）、健康（24h 成功率、连续失败、最近错误、下次轮询）、最近调用；底部按状态给重新授权 / 暂停 / 恢复 / 断开（断开二次确认）。未配置时抽屉变为配置表单（端点 / 认证方式 / 凭据），「保存并连接」后进入已连接。小组管理员只读，只看到「关闭」。
    - Webhook 订阅与服务账号：状态、最近投递 / 凭据轮换；死信直接链到队列页。
  - **小组参数**：
    - 小组选择器：平台管理员可切换任意小组；小组管理员锁定本组，其他小组禁用并说明原因。
    - 归属提示：连接与凭据由平台统一维护；小组参数归属各组，由小组管理员自行维护，平台管理员可代为修改（审计标注「代为」）。
    - 参数表列：集成 / 本组默认值 / 来源 / 更新 / 维护；四行分别为 Helix / JIRA / Teams / SolMan（有使用参数的集成）。本组默认值用 chips 展示每个字段的有效值（已覆盖 = 蓝、继承 = 灰）；来源为「已覆盖 N 项」或「继承平台默认」；更新显示最近修改人与时间。
    - 参数抽屉：逐字段编辑（文本 / 下拉），字段下常驻「平台默认：X · 继承中 / 本组已覆盖」；本组维护时顶部提示「本组参数由小组管理员自行维护」，平台管理员改其他组时提示「由小组管理员主责维护，本次修改以代为维护记入审计」；底部「恢复平台默认」（二次确认）与「保存」。只读时字段禁用，只保留关闭。
    - 表底说明：参数只影响本组新建对象与默认选择，不回溯历史数据。
- **审计日志**：顶部类型 chips（全部 / 成员 / 小组 / 集成 / 安全）按类过滤；表格列：时间、操作人、操作、对象、来源、结果；底部说明 + 「导出」。平台管理员看全量，小组管理员看本组。
- **无权限页**：图形 + 「需要管理员权限」+ 一句原因（当前账号是财务共享组的普通成员）+ 返回工作台 / 个人设置 + 联系本组管理员 林桦或平台管理员；不显示任何管理数据。
- **状态**：平台管理员 / 小组管理员（平台管理员可切换小组、维护全部组参数；小组管理员在小组参数锁定本组、在连接与凭据只读）；参数行两种来源态（继承平台默认 / 已覆盖 N 项）；无权限；集成 5 态；维护动作执行中 / 失败；审计空状态。
- **交互**：切换 tab 与小组卡；集成与维护内切换二级视图；小组参数切换小组、打开参数抽屉、保存、恢复平台默认；成员行操作；维护抽屉动作；待处理条跳转；审计类型过滤。旧链接 `#/settings?tab=groups|integration` 重定向到对应 tab，`?tab=security` 映射到 `?tab=account`。

`vscode.html` 是独立的插件设计原型，**不在 Web 工作台的导航或页面中提供入口**，仅作为设计交付物单独打开；插件内部界面见 [04-vscode-plugin.md](04-vscode-plugin.md)。 Web 界面里的「在 VSCode 打开」只演示任务上下文与 worktree 的生成流程，不再跳转到插件原型。

## 全局浮层

### 通知抽屉

- 路由：任意页面点击顶栏铃铛；`?notif=1` 可直接打开（截图：[notifications](../screenshots/notifications.png)）。
- 内容：待处理 / 全部；通知项含图标、标题、描述、来源、时间、行动按钮。
- 操作：去处理（跳转）、全部已读、通知设置（→ `#/settings?tab=notify`）。

### 命令面板

- `⌘K` / `Ctrl+K`；`?cmd=1` 可直接打开（截图：[command-palette](../screenshots/command-palette.png)）。
- 分组：跳转（页面）、命令（确认设计 / 提交上线 / 在 VSCode 打开 / 管理控制台）、需求（按标题搜索）。
- 键盘：↑↓ 选择、Enter 打开、Esc 关闭。

### 详情抽屉

- 用于 CRQ、队列、Webhook、外部调用的详情；620px；含状态、字段、日志、操作。
- 保底操作：复制 trace / 重放 / 重试失败步骤。

### 确认弹窗

- 用于门禁通过 / 驳回、提交审批、创建工单、解除设备等不可逆操作。
- 结构：标题 + 说明 + 关键信息 / 风险 + 取消 / 确认；危险操作使用红色按钮。

## 响应式与状态清单

| 场景 | 处理 |
| --- | --- |
| ≤1180px | 详情侧栏下沉；看板横向滚动；集成卡片两列 |
| ≤960px | 侧栏抽屉；隐藏次要列；表格横向滚动；命令面板全宽 |
| ≤640px | 单列；页头动作换行；抽屉全宽 |
| 空状态 | 给出下一步动作（新建 / 领取 / 连接） |
| 加载 | 骨架或按钮 loading；不阻塞整页 |
| 错误 | 说明「现在该做什么」+ 重试入口 |
| 权限 | 无权限页（不显示管理数据，给联系人与返回入口）；可查看的 IT 工具页显示只读条（主操作隐藏）；不可见的 IT 工具页渲染「当前视角不可用」页；动作不满足边界时禁用 + 原因；不静默失败、不静默重定向 |
| 减少动效 | 动画时长与延迟均为 0（含交错）；内容直接可见；序列等待自动压缩 |
