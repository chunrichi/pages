# 06 · 角色、权限与管理

> 本文回答四个评审中暴露的落地问题：**管理界面怎么进、集成维护怎么做、SAP 业务与 SAP IT 到底差在哪、小组成员维护的权限边界**；最后一节是设计合理性检查与结论。  
> 原型入口：[`app.html#/admin`](../app.html#/admin) · 个人设置：[`app.html#/settings`](../app.html#/settings)

## 1. 问题：三个概念被混在一起

| 现状 | 后果 |
| --- | --- |
| 设置页常驻「管理员」徽标，任何角色都能看到集成凭据、Webhook、服务账号 | 权限不可信；业务用户看到不该看的东西 |
| 顶栏「SAP 业务 / SAP IT」切换只改总览文案，导航与动作完全一样 | 角色差异是假的，业务用户也能进队列、Agent、CRQ |
| 集成卡片的「配置」按钮没有行为，测试 / 同步 / 查看日志都弹同一个 toast | 维护入口不可用，异常没有修复路径 |
| 成员表只有「角色」列，邀请 / 移除 / 调整对所有人开放 | 谁有权维护成员、能维护到什么范围，没有定义 |
| 全局「保存」按钮不属于任何表单 | 用户不知道保存了什么 |

根因：**工作视角（怎么看）、业务角色（做什么）、管理权限（能管什么）被当成了同一个东西。** 三者正交，必须拆开。

## 2. 模型：视角 / 角色 / 权限

### 2.1 三层定义

| 层 | 取值 | 谁决定 | 影响 |
| --- | --- | --- | --- |
| **工作视角** `view` | SAP 业务 / SAP IT | 账号有双视角时自助切换；单视角账号不显示切换器 | 导航、默认落地页、首页信息、页面可操作项 |
| **业务角色** `role` | 业务 / 需求顾问 / 开发 / 测试 / Basis | 小组管理员调整 | 任务类型、门禁职责、文档评审身份 |
| **管理权限** `admin` | 平台管理员 / 小组管理员 / 无 | 平台管理员授予；小组管理员可任命本组管理员 | 是否出现「管理」入口，以及管理范围 |

**约束**

- 视角是**视图**，不改变权限：切到 SAP IT 视角不会获得 IT 的写权限；权限不足时页面显示只读与原因。
- 业务角色与小组绑定：一人一组（沿用 v2.1 决策），角色由小组关系决定。
- 管理权限单独授予，不隐含在业务角色里。一个人可以既是 SAP 业务，又是本组管理员。
- 管理权限只有两级：平台级（全部小组、集成、审计）与小组级（本组成员与本组规则）。不设第三级自定义角色。

### 2.2 演示账号（原型）

| 字段 | 值 |
| --- | --- |
| 账号 | 陈曦 · chen.xi@sap.example |
| 小组 | 财务共享组 · FIN-SH |
| 业务角色 | SAP 业务 |
| 工作视角 | SAP 业务 + SAP IT（双视角，可切换） |
| 管理权限 | **平台管理员** |

> 原型把「业务 + 平台管理员」放在同一账号上，是为了在一份账号里同时演示业务界面与管理界面；真实部署中平台管理员通常是 IT / 工具管理员。成员表里另有「小组管理员」样例（林桦），用来展示两级权限的差别。

### 2.3 权限矩阵

`●` 可操作 · `○` 只读 · `—` 不可见

| 能力 | 平台管理员 | 小组管理员 | 成员 | 说明 |
| --- | --- | --- | --- | --- |
| 管理控制台入口 | ● | ● | — | 成员直接访问 URL 显示无权限页 |
| 创建 / 归档小组 | ● | — | — | 小组 Key 创建后不可改 |
| 管理全部小组 | ● | — | — | 小组管理员只能管理本组 |
| 邀请 / 移除本组成员 | ● | ● | — | 移除需二次确认并写审计 |
| 调整成员业务角色 | ● | ● | — | 不能修改自己的业务角色（避免自提权） |
| 任命 / 取消小组管理员 | ● | ● | — | 不能修改自己的管理权限；最后一名小组管理员不可移除或降级 |
| 成员跨组转移 | ● | — | — | 单组模型的唯一例外，必须平台管理员执行 |
| 本组默认模板 / 审批人 | ● | ● | — | 只影响新建对象，不回溯历史 |
| CRQ 本组模板（字段 / 下拉选项 / 版本） | ● | ● | ○ | 只显示本组模板，其他小组不可见 |
| 平台基础模板 | ● | — | — | 对全部小组生效；小组只继承，不提供跨组模板视图 |
| 集成连接与凭据（端点 / 启停 / 重连） | ● | ○ | — | 连接是平台级共享资源 |
| 本组集成参数（默认值） | ●（代为） | ●（主责） | — | 归属小组；平台管理员可代为维护并留痕 |
| 全部小组的集成参数 | ●（代为） | — | — | 平台管理员可切换小组代为维护 |
| Webhook / 服务账号 | ● | ○ | — | 同上 |
| 审计日志 | ● | ○（本组） | — | 平台管理员看全量 |
| CRQ / ChaRM 操作 | 随视角 | 随视角 | — | 业务视角只读 |
| 队列 / Agent 操作 | 随视角 | 随视角 | — | 业务视角不可见 |
| 个人设备重绑 / 通知规则 | ● | ● | ● | 始终自助 |

> CRQ 模板与「小组集成参数」不同：集成参数允许平台管理员代为维护其他小组，**模板不做跨组维护**——小组模板只有本组可见；平台管理员只多维护一层平台基础模板。模板下拉选项与默认值从 ChaRM 值列表拉取后勾选（见 [02 §6.2](02-关键流程.md#62-模板模型)）。

## 3. 管理界面

### 3.1 入口（三个，都收敛到同一路由）

1. **侧栏「管理」组 → 管理控制台**：仅管理员可见；普通成员侧栏没有这一组。
2. **头像菜单 → 管理控制台**：管理员可见。
3. **侧栏小组卡**：管理员点击直达 `#/admin?tab=groups`；普通成员点击进 `#/settings` 看只读的小组信息。

无权限处理：

- 直接访问 `#/admin` 时渲染**无权限页**：说明当前账号是普通成员、应联系谁、提供「返回工作台」。
- 不静默重定向、不显示半截界面。

### 3.2 结构

```text
#/admin?tab=groups|integrations|audit
├─ 页头：管理控制台 · [平台管理员 / 小组管理员]
├─ 待处理条（有异常时才出现，仅小组与成员 tab）：集成需维护 / 邀请待接受 → 一键去处理
├─ Tabs：小组与成员 / 集成与维护 / 审计日志
└─ 内容区
```

「待处理条」是管理页的处理入口：它把「哪个按钮该点」变成「哪里出了问题」，点进去直接落在对应 tab 并打开维护抽屉。

### 3.3 小组与成员

**小组卡**（三张，既是概览也是选择器）

- 显示：小组名、Key、成员数、小组管理员、默认模板；我的小组高亮。
- 点击卡片切换下方成员表；「管理小组」打开配置弹窗（名称 / Key 只读 / 默认模板 / 默认审批人 / 管理员）。
- 「新建小组」只对平台管理员出现；小组管理员隐藏而不是禁用（无权限的动作不占位）。

**成员表**（选中小组）

| 列 | 内容 |
| --- | --- |
| 成员 | 头像 + 姓名；待接受邀请的成员带「待接受」状态 |
| 邮箱 | 企业邮箱 |
| 业务角色 | SAP 业务 / 需求顾问 / SAP IT · ABAP / Basis · ChaRM / 测试 |
| 管理权限 | 平台管理员 / 小组管理员 / —（普通成员） |
| 设备绑定 | 已绑定设备名 / 未绑定；待接受邀请显示「邀请 11-09 发出」 |
| 最近活跃 | 相对时间 |
| 操作 | 行菜单 |

> 去掉了 v2.1 的「所属小组」列：一人一组时该列恒等于当前小组，是冗余信息；腾出的位置给「管理权限」，让权限直接可读。

**行操作**（弹窗列出，按权限与目标成员动态启用）

| 操作 | 谁能做 | 边界 |
| --- | --- | --- |
| 调整业务角色 | 平台 / 小组管理员 | 不能改自己的业务角色（避免自提权） |
| 设为 / 取消小组管理员 | 平台 / 小组管理员 | 取消最后一名小组管理员：禁用并给出原因 |
| 重新发送绑定链接 | 平台 / 小组管理员 | 只对「未绑定 / 待接受」出现 |
| 解除设备绑定 | 平台 / 小组管理员 | 二次确认，说明旧设备立即失效 |
| 转移小组 | 仅平台管理员 | 对小组管理员显示禁用 + 「需平台管理员」；历史需求保留原小组归属 |
| 移除成员 | 平台 / 小组管理员 | 最后一名管理员禁用；二次确认写明「历史需求与任务保留」 |

**邀请成员**：平台管理员可选小组；小组管理员的小组字段锁定为本组。邀请后成员进入「待接受」状态，可重发或撤销。

**右侧两张卡**

- **权限规则**：两级管理员的职责、最后一名管理员保护、跨组转移、审计留痕。用定义代替说明文字。
- **成员变更**：最近 7 天的变更（谁把谁改成了什么），与审计日志互补：这里是小组视图，审计是全量。

### 3.4 无权限页

- 图形 + 标题「需要管理员权限」+ 一句原因（当前账号是财务共享组成员）。
- 给出下一步：联系本组管理员 林桦 / 平台管理员；返回工作台。
- 不显示任何管理数据，避免「看得见点不动」的挫败感。

## 4. 集成维护

### 4.1 状态机

| 状态 | 含义 | 卡片主动作 | 维护抽屉里的主操作 |
| --- | --- | --- | --- |
| 已连接 | 最近调用成功 | 测试连接 | 轮换凭据 / 暂停 / 断开 |
| 同步中 | 正在轮询或批量同步 | 查看同步日志 | 暂停 / 断开 |
| 需处理 | 凭据过期、鉴权失败、连续失败 | 重新授权（直接弹授权） | 重新授权 / 查看失败原因 |
| 已停用 | 被管理员暂停 | 恢复 | 恢复 / 断开 |
| 未配置 | 新建但未填凭据 | 配置连接 | 填写连接与凭据 |

状态决定动作，动作改变状态：不允许出现「已连接」却点不到修复入口的卡片。

### 4.2 卡片

```text
[icon] 名称           [状态]
       一句话说明
─────────────────────────────
端点 / 客户端 / 最近调用（三行 kv）
─────────────────────────────
[测试连接]              [维护]
```

- 主动作按状态变化（见 4.1）；「维护」始终打开维护抽屉。
- 需处理的卡片额外显示一行错误摘要（例如「401 凭据已过期 · 同步已暂停 3 小时」）。
- 去掉 v2.1 的齿轮「配置」图标：图标按钮不解释自己，改成一个有文字的「维护」。

### 4.3 维护抽屉

| 区块 | 内容 | 操作 |
| --- | --- | --- |
| 连接信息 | 端点、客户端、认证方式、维护人、最近维护 | — |
| 凭据 | 类型、掩码、上次轮换、到期时间 | 轮换凭据 |
| 健康 | 24h 成功率、连续失败、最近错误、下次轮询 | 测试连接 |
| 最近调用 | 5 条调用记录（时间 / 操作 / 结果 / 耗时） | 查看全部 → 队列 |
| 底部 | 暂停 / 恢复、断开连接 | 断开需二次确认并说明影响 |

所有维护动作：写审计（谁、何时、对哪个集成、做了什么、结果），并回写卡片状态与「最近调用」。

### 4.4 Webhook 与服务账号

- Webhook 订阅：事件 / 目标 / 状态 / 最近投递；新建订阅用弹窗；死信直接链到队列页对应事件。
- 服务账号：账号、作用域、凭据来源、上次轮换；提供「轮换凭据」（平台管理员）。凭据只在服务端使用，不下发客户端。

### 4.5 两级配置：通用连接 + 小组参数

集成不是一个整体，它有两层设置，维护人和归属都不同：

| 层 | 内容 | 谁维护 | 归属 |
| --- | --- | --- | --- |
| **通用（平台级）** | 端点、认证方式、凭据、启停、健康、Webhook 订阅、服务账号 | 平台管理员 | 全局一份 |
| **小组参数** | 默认工作空间 / 项目 / 工单类型 / 指派组、默认频道、CRQ 默认模板与请求类型 | 小组管理员（本组）；平台管理员（任意组） | 每组一份 |

**为什么分层**：连接是共享基础设施，凭据和端点只能有一份；但「连上之后怎么用」是业务差异——财务共享组的 Helix 默认项目与制造组不同，JIRA 的默认 Project、Teams 的默认频道、SolMan 的默认 CRQ 模板也一样。把这些塞进平台配置会让平台管理员替所有组做业务决定。

**继承与覆盖**

- 平台为每个参数给出默认值；小组可以只覆盖关心的字段，其余显示「继承平台默认」。
- 覆盖值以小组为准；「恢复平台默认」清除覆盖，不做静默改写。
- 参数只影响本组**新建**对象与默认选择，不回溯历史数据。

**归属、权限与审计**

- **参数归属小组**：每组一份，主责维护人是该组的小组管理员——业务默认值应该由最懂业务的那组人定。
- 平台管理员：维护连接与全部小组参数（可切换小组）；维护非本组参数属于「代为维护」，界面提示、审计标注「代为」。
- 小组管理员：自行维护本组参数；连接、凭据、Webhook、服务账号只读，并说明原因。
- 普通成员：不可见。
- 小组参数变更写审计（对象 = 小组 + 集成 + 变更字段；本组维护与平台代为维护分开标注）。

**界面**

- 集成与维护 tab 内分两个子视图：**连接与凭据**、**小组参数**。
- 小组参数视图：小组选择器（小组管理员锁定本组）+ 每个集成一行（本组默认值摘要、来源、更新人、维护）；维护抽屉逐字段编辑，附「平台默认」提示与「恢复平台默认」。
- 连接与凭据视图保留原有集成卡片；Helix 这类需要较多分组默认值的集成在卡片上直接给出「小组参数」入口。

**示例**

| 集成 | 平台默认（通用） | 小组参数示例（财务共享组） |
| --- | --- | --- |
| Helix | 工作空间 `SAP-COMMON` · 项目 `SAP-CORE` | 工作空间 `FIN-SH-WS` · 项目 `FIN-AP` · 默认工单类型 `需求` · 指派组 `财务共享组` |
| JIRA | Project `SAP` · Issue 类型 `Story` | Project `SAP-FIN` · 同步方向 `双向` |
| Microsoft Teams | 频道 `#sap-delivery` | 频道 `#fin-sap-it` · @ `财务共享组` |
| SolMan CRQ API | 模板 `通用 v1` · 请求类型 `ZSAP_CHG` | 模板 `财务共享 v3` |

## 5. SAP 业务 与 SAP IT 的区别

一句话：**业务视角做「提、看、确认」，IT 视角做「接、做、发」。** 差异必须同时体现在导航、默认落地、页面内容与动作四层，只改文案不算。

| 维度 | SAP 业务 | SAP IT |
| --- | --- | --- |
| 默认落地 | 总览（需求视角） | 任务台 |
| 侧栏 | 总览 / 需求 / **待我确认** / 知识库 / 个人设置 | 总览 / 需求 / **任务台** / 文档评审 / CRQ / ChaRM / 队列 / Agent / 知识库 / 个人设置 |
| 总览 | 需求进度、待我确认、上线窗口、AI 运行 | 任务与租约、等待回答、队列健康、Agent 运行 |
| 任务 | 「待我确认」：文档门禁、上线审批、澄清问题 | 「任务台」：可领取 / 进行中 / 等待回答 + VSCode |
| 需求 | 我的需求、新建、确认文档 | 全部需求、受理、补负责人、推进阶段 |
| 文档评审 | 通过 / 驳回、批注 | 技术检查、批注、交给 AI 生成新版本 |
| CRQ / ChaRM | 只读（从需求详情进入） | 创建、编排、Basis 审批 |
| 队列 / Agent | 不可见 | 操作、重试、暂停 |
| 知识库 | 只读 | 维护来源与索引 |
| 管理 | 管理员可见 | 管理员可见 |

实现约定：

- 导航项带 `data-view` / `data-cap`，切换视角时只显示当前视角的项；不显示置灰项。
- 业务视角访问 IT 工具页分两种处理：
  - **可查看**：CRQ 列表、ChaRM、知识库 → 顶部只读条，主操作隐藏，保留筛选、搜索与详情；只读条提供「切换到 SAP IT 视角」。
  - **不可见**：队列与事件、Agent 运行、新建 CRQ、CRQ 模板 → 渲染「当前视角不可用」页，说明归属并给出切换视角 / 返回工作台。
- 视角切换后若当前路由不在新视角的导航里，落到该视角的默认页；页面内切换由只读条与守卫页的按钮完成。

原型落地范围：导航、默认落地、总览（业务需求列表 / IT 任务列表）、待我确认 / 任务台、工具页只读与守卫页、需求详情的 VSCode 入口已按视角区分；需求页业务视角隐藏「同步 JIRA」与 Backlog 视图，CRQ 列表在业务视角只显示本组工单。需求列表未按人过滤（由「我负责的」筛选完成）；文档评审、需求详情、上线审批的按钮级权限由后端校验，原型未逐按钮禁用，避免同一页面出现两套交互。

## 6. 个人设置（与管理的边界）

| 归属 | 内容 | 路由 |
| --- | --- | --- |
| **个人** | 我的账号（姓名 / 邮箱 / 小组 / 业务角色 / 管理权限）、设备绑定与安全事件、通知规则 | `#/settings` |
| **管理** | 小组成员与规则、集成维护、审计 | `#/admin` |

- 个人设置不再出现「管理员」徽标、集成凭据与全局「保存」。
- 安全策略（一次性链接有效期、设备凭证 180 天）是平台策略：个人页只读展示，修改在管理侧。
- 我的账号里显示管理权限；是管理员时提供「前往管理控制台」的链接，普通成员没有。

## 7. 原型实现约定

### 7.1 运行时 API（`assets/app.js`）

```js
SA.auth.account   // { name, email, groupKey, groupName, businessRole, views[], admin }
SA.auth.can(cap)  // "admin.access" | "admin.members.remove" | "admin.integrations.manage" | …
SA.view           // "business" | "it"
SA.setView(view)  // 切视角：导航、用户卡、默认落地；不可见路由回默认页
SA.isReadOnly()   // 业务视角访问 IT 工具页
SA.viewDefaultRoute()
```

能力字符串：`admin.access`、`admin.groups.create`、`admin.groups.manage`、`admin.members.invite`、`admin.members.role`、`admin.members.admin`、`admin.members.transfer`、`admin.members.remove`、`admin.integrations.manage`、`admin.audit.view`。

### 7.2 路由

| 路由 | 页面 |
| --- | --- |
| `#/settings?tab=account` | 个人设置 · 账号与设备（默认） |
| `#/settings?tab=notify` | 个人设置 · 通知规则 |
| `#/admin?tab=groups` | 管理控制台 · 小组与成员（默认） |
| `#/admin?tab=integrations` | 管理控制台 · 集成与维护 |
| `#/admin?tab=audit` | 管理控制台 · 审计日志 |

兼容：`#/settings?tab=groups|integration` 重定向到 `#/admin` 对应 tab；`?tab=security` 映射到 `?tab=account`。

演示参数：

| 参数 | 作用 |
| --- | --- |
| `#/admin?as=member` | 以普通成员身份查看无权限页 |
| `#/admin?as=groupadmin` | 以小组管理员身份查看（集成连接只读、只能维护本组参数） |
| `#/admin?as=platform` | 恢复平台管理员视角（预览状态在管理控制台内保持） |
| `#/admin?tab=integrations&maintain=jira` | 直接打开 JIRA 维护抽屉 |
| `#/admin?tab=integrations&sub=params&group=FIN-SH` | 打开小组参数视图 |
| `#/admin?tab=integrations&sub=params&group=FIN-SH&edit=helix` | 直接打开 Helix 小组参数抽屉 |
| `#/tasks?view=it`、`#/home?view=it` | 以 SAP IT 视角打开（截图用） |

## 8. 设计合理性检查

| # | 问题 | 结论 / 处理 |
| --- | --- | --- |
| 1 | 「管理员」是静态徽标，与账号无关 | 改为由 `admin` 权限驱动；无权限不显示管理入口，直接访问显示无权限页 |
| 2 | 业务账号能看到集成凭据、Webhook、服务账号 | 集成是平台级资源：拆到管理控制台，且小组管理员只读 |
| 3 | 角色切换只改总览文案 | 差异落到导航 / 默认落地 / 首页 / 任务页 / 只读条四层 |
| 4 | 「配置」按钮无行为 | 改为「维护」抽屉：连接、凭据、健康、调用日志、启停与断开 |
| 5 | 集成状态只有「已连接 / 同步中」 | 补「需处理 / 已停用 / 未配置」三态，每态都有明确修复动作 |
| 6 | 测试 / 同步 / 查看日志都是同一个 toast | 每个动作有独立结果与副作用（状态、最近调用、审计） |
| 7 | 全局「保存」按钮不属于任何表单 | 删除；保存动作跟随各自表单 |
| 8 | 成员表「所属小组」列恒为同一值 | 去掉冗余列，换成「管理权限」 |
| 9 | 「12 人 · 1 位待接受邀请」但表里没有待接受行 | 补待接受状态行与重发 / 撤销 |
| 10 | 邀请成员可选任意小组 | 按权限收敛：小组管理员锁定本组，跨组需平台管理员 |
| 11 | 移除 / 降级最后一名管理员没有保护 | 禁用并说明原因；变更写审计 |
| 12 | 跨组转移与「一人一组」看似矛盾 | 保留为平台管理员的显式操作，历史归属不迁移，并写审计 |
| 13 | 通知规则写「按角色生效」，语义模糊 | 改为事件 × 渠道；与视角无关，按账号生效 |
| 14 | 侧栏「文档评审」固定指向 R-2041 | 业务视角不再保留固定入口，改从「待我确认 / 需求详情」进入；IT 视角保留 |
| 15 | 管理操作不可追溯 | 管理控制台增加审计日志 tab；成员变更、集成维护都写入 |
| 16 | 集成只有平台级维护，各组的默认值无处安放 | 拆成两级：通用连接归平台，小组参数归各组并可继承平台默认（见 4.5） |
| 17 | 小组卡三张但用户只属于一组，像是可切换 | 小组卡明确为「管理员视图」的选择器；我的小组高亮；普通成员看不到三张卡 |

**没有改的（仍成立）**：一人一组；文档只支持 Markdown；批注可交 AI 生成新版本；VSCode 为独立原型；浅色克制视觉。

## 9. 待确认

1. 平台管理员是否按环境（DEV / QAS / PRD）再分权？原型按单环境处理。
2. 小组成员是否允许「申请转组」自助发起审批？原型只保留平台管理员直接转移。
3. 集成维护是否需要审批（四眼原则）？原型只做审计留痕。
4. 业务视角是否需要只读的队列健康摘要（例如「本需求的通知是否送达」）？当前放在需求详情里。
5. 集成是否需要按组启停（某组不用 Helix）？当前只做参数级差异，启停仍是平台级。
